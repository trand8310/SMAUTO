# PWTest 与 HumanTouchP3

PWTest 是本地诊断工具。它使用 Patchright 和独立的 HumanTouchP3 会话测试页面操作，不连接业务网站，也不修改 SMAd 使用的 v3。

## 使用

1. 构建并运行 `dotnet run --project PWTest/PWTest.csproj`，或打开 `PWTest/bin/Debug/net8.0-windows/PWTest.exe`。
2. 在界面选择实际存在的 Chromium 可执行文件。用户目录默认为每次打开 PWTest 新生成的临时路径，可自行修改；程序不会删除该目录。参数框预置用户提供的 Chromium 125 参数，可编辑后点击“启动浏览器”。参数框只填写 `--` 参数；用户目录单独填写，不能重复指定 `--user-data-dir`。`%PROFILE%` 会替换为用户目录，用于默认的日志路径；批处理中的 `%~dp0` 需改成绝对路径或 `%PROFILE%`。程序始终打开本地诊断页，不会自动打开示例中的外部 URL。
3. 使用持久浏览器上下文，关闭 Playwright 的固定视口模拟，由内核和启动参数决定实际显示；启动完成后日志记录浏览器报告的屏幕、视口与 DPR。自定义参数依赖对应内核实现，并且 Patchright 仍会附加自身默认启动参数；不要把参数值当作实测显示结果。
4. 页面顶部默认显示紧凑工具栏；点击“设置”展开采集和姿势控制，再点“收起”以留出操作空间。勾选“内部容器”才显示内层滚动测试区，取消勾选后隐藏。选择姿势，页面会以蓝色、橙色或绿色显示右拇指、左拇指或右食指的大致活动范围及滑动方向；可在页面下拉框隐藏示意。示意图不会拦截触摸，范围是未校准的假设，不是可触达边界。页面默认显示粉色的触摸轨迹，白圈为起点，黄点为当前触点，粉点为抬手位置；轨迹保留到下一次触摸，也可隐藏或清除。轨迹来自页面收到的 touch 事件，使用主视口坐标，不代表 P3 的计划轨迹或手指抬起后的惯性滚动。“甩动强度”可选随机、轻、中、强，仅作用于快甩和快速浏览。随机模式每次甩动选择强度，力度影响轨迹长度、时长和计划抬手速度；并不保证实际惯性距离严格排序，触点压力也不等于页面滚动距离。导出的动作结束记录包含强度及计划轨迹摘要，实际滚动以页面事件为准。PWTest 打开浏览器后自动开始连续采集，可多次点击慢滑、快甩、阅读、快速浏览或点击按钮，动作不会自动弹出保存框。等待惯性停止后，点击“停止并导出”保存同一份 JSON；如取消保存，可再次导出。停止后再执行的动作不会记录，点击“开始新采集”将清除旧记录并重新开始。
5. 真机与电脑连接同一个可信局域网，在手机浏览器中打开窗口日志里的局域网地址。在页面选择对应姿势示意，输入设备/姿势/动作标签，点击“开始新采集”，操作页面并等滚动停止，点击停止、下载 JSON，将文件传到电脑。页面顶部控制区的触摸事件不计入采集。
6. 点击“对比两个 JSON”，分别选择真机和 PWTest 文件。对比仅为描述性统计；没有抬手后滚动样本时显示无数据，不能据此判断完全没有惯性。原始事件和设备环境保留在 JSON 中。

测试页面在程序运行期间通过随机端口监听本机所有网络接口，供局域网手机打开；它只提供只读页面，不接收上传。仅在可信网络使用，Windows 防火墙可能需要允许访问。关闭窗口后服务停止；不要用于公开网络。采集包含页面坐标、屏幕和 user agent，不要在其他页面使用或分享含敏感信息的记录。


## 阅读与惯性测试

PWTest 增加“停留阅读 2 秒”“向上微调”“向下回看”“内部容器上滑”“甩动并观察惯性”和“甩动并测试制动”。内层容器需要先在诊断页面勾选“内部容器”，且实际落点必须命中指定滚动容器；不能滚动或被遮挡时返回无动作，不回退为整页滑动。页面的“惯性停止测试区”是固定的、显式标记的非交互区域，专供本地夹具测试。

观察动作记录目标类型、观察期间是否移动、是否稳定及起止滚动位置；制动动作仅在短时观察检测到滚动、且调用方提供标记的非交互测试区时尝试触摸。触摸派发与随后稳定是分别记录的事实，不能单凭两者证明触摸导致惯性停止；如果没检测到滚动或测试区不可用，不会触摸，也不会自动重试。不要把此制动方法用于未知业务页面：标记和 DOM 检查无法排除页面脚本为区域注册点击监听器。停留与观察遵循同一输入协调器，并支持取消；不能滑动时阅读模式保留剩余静态停留。阅读浏览在每次阅读滑动和停留后，低概率执行一次微调或回看；调用方可关闭 `includeReadingAdjustments`，时间预算或取消令牌仍然生效。

## P3 的边界

P3 以 HumanTouchP2.Enhancedv3 为源码基础，将输入协调、CDP 派发、超时、触点释放和滚动检测维护在自己的项目中，不引用或加载 v3 程序集。三个姿势使用一位操作者在单台设备上的样本作初步校准，不能代表人群或完整的真实手部模型；采样与局限见 `docs/HumanTouchP3-真机样本校准-20261030.md`。阅读、普通、快速浏览采用现有意图；行为和惯性仍需通过真机数据校准。停止/取消时执行 P3 自己的触点清理。PWTest 不接入原有任务，也不修改现有 SMAd。

## 验证

`dotnet run --project tests/HumanTouchP3.RegressionTests -- ../pc_chrome.packed/135.0.7049.119/chrome.exe` 使用本地夹具检查三种姿势的触摸与滚动。不同内核和真机仍需单独采样比较。参数解析和自定义参数启动使用隔离用户目录测试；本机 Chromium 135 headless 可完成触屏，但本机 `125/chrome.packed/Chrome-bin/chrome.exe` headless 在页面启动时以 `Target crashed` 失败，日志出现 `blink.mojom.fingerprint.FingerprintService` binder 错误。它不是用户给出的 `chromium125/src/out/Release/chrome.exe`，该目标内核仍需用户指定后验证。
