# 浏览器独立生命周期日志

每次执行默认启用，不需要打开额外开关。文件位于 MainClient 可执行文件所在目录：

```text
logs/browser-lifecycle/browser-20261013-<客户端进程号>.log
```

使用北京时间按天分文件，客户端重启后使用新的进程号。普通 app 日志会显示实际文件路径。每行是一条 UTF-8 JSON 记录，包含中文说明、时间、客户端 PID、executionId、事件、来源和详细数据。浏览器 PID 单独记录在 data 中，不与客户端 PID 混淆。每条记录写完立即释放文件句柄，运行期间可以复制日志。

## 可以判断哪些关闭原因

同一次浏览器执行通过 executionId 串联这些事件：

| 事件 | 含义 |
| --- | --- |
| worker.begin / worker.stage | 任务 ID、内核、代理/显示模式和入口、首次点击、落地二跳、详情停留等执行阶段 |
| process.launch_requested / process.started / process.endpoint_ready | 启动参数摘要、浏览器 PID、TTL 与自动 CDP 端点就绪 |
| connection.connected / connection.disconnected | 连接建立或断开时进程是否已经退出 |
| page.action_begin / page.input_dispatched / page.action_end | 动作开始、输入派发与最终导航/点击结果；派发完成不等于跳转成功 |
| page.closed / page.crashed / page.initialization_failed | 普通页面关闭、渲染崩溃、新页面初始化失败 |
| worker.exception / worker.ending | 原始异常、最后阶段、当前 PV、URL、取消状态、流程是否成功和执行结束原因 |
| session.stop_requested / process.monitor_stop | 最初的停止分类、触发来源、原因和当时进程状态；CDP 断开后确认崩溃时另记升级 |
| session.reclaim_begin / process.kill_requested | 程序开始回收及主动结束所属进程树的时间 |
| process.exited / process.reclaim_end / session.reclaim_end | 是否发生在回收中、退出码、强制终止、退出确认、清理错误与 Chromium stderr 最后 32 行 |
| worker.result / profile.cleanup_end | 最终访问和点击 PV、执行结果、目录清理结果 |
| application.* | 客户端启动、退出、未处理异常及重启请求 |

`Completed` 表示流程完成后主动回收；`ExecutionFailed` 表示业务流程失败后回收；`StartupFailed` 表示启动或初始化失败；`LifetimeExpired` 表示浏览器自身 TTL 到期；`ProxyFailed` 表示确认代理故障；`DriverDisconnected` 与 `CdpDisconnected` 分别表示驱动和浏览器连接失效。

不要只看最后一条“关闭”：先看最早的停止请求及 worker.exception，再对照最后阶段与 process.exited。当日志先出现 process.kill_requested，随后出现非零退出码时，该退出码可能是程序主动终止导致，不能证明内核自己崩溃。CdpDisconnected 只证明连接失效；进程提前退出也可能是手动关闭，需结合原生诊断判断。上游取消日志记录 CallerToken，无法仅凭令牌推断是人工停止还是上层超时。

用户目录占用只记录为清理错误，不当成浏览器崩溃。新页面初始化失败只记录其目标诊断，不通过日志增加停止或重试。

## 发送哪些文件

问题发生后，复制当天 `logs/browser-lifecycle` 中的日志文件发来。若当天重启过客户端，发送当天全部文件；并说明浏览器消失的大致时间。独立日志会关联已有 page-actions 日志路径，需要进一步分析触屏轨迹时再补发对应动作文件。

诊断日志不保存完整任务参数、代理命令行、请求头或响应正文；记录的 URL 隐去用户信息、查询参数和 fragment，密码、token、Authorization 和 Cookie 等常见字段也脱敏。站点路径、错误码、阶段及异常栈仍保留。文件写入失败不影响执行，客户端启动/回收日志会提示日志写入错误，解除占用后恢复写入。

日志按日期和客户端进程分文件，不自动删除历史记录。若客户端被外部强制终止或系统断电，可能没有最终回收事件；此时应保留文件中的最后阶段，不能补推不存在的成功或失败结果。
