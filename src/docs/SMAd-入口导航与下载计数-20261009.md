# 入口导航与下载计数

页面初始化仍注册一次下载事件，用于取消下载和记录诊断。`BusinessDownloadsEnabled` 初始为 false，每次 PV 重置以及入口导航开始时关闭；入口网页通常通过 DOMContentLoaded 与 body 可见检查后启用。导航或就绪等待超时后，若本次主文档收到 2xx 响应、当前 URL 与该响应一致且页面已有可见内容，可接受当前页面并继续；记录超时降级，不要求 DOMContentLoaded。无响应、空内容、错误状态、附件或下载不能通过这一判断，仍按既有规则处理；不将调用方取消转换成成功。

`wm.m.sm.cn` 搜索入口在等待 DOMContentLoaded 期间，若已提交的本次主文档是 2xx、无下载或附件，并且广告标记在视口中连续两次可见，可提前判定搜索结果就绪。未看到广告、隐藏广告、主文档状态未知及错误页不能走此路径；无广告仍依赖原有检测流程，不能把广告尚未加载当作无广告。底层导航任务继续观察其完成或异常；入口加载后等待仍按配置执行。日志分别记录入口就绪耗时和加载后等待时长。

导航先于广告探测结束时立即转入导航结果处理，不等待未完成的探测；迟到探测结果只观察，不用于之后的页面或 PV。每次 PV 独立重置广告数量和入口曾观察到广告的证据。

广告检测仍按现有业务选择器计数。选择器匹配为零时，检查可见的“广告”或“推广”标签；若存在标签，或入口就绪阶段曾观察到广告，则有界复查。复查仍矛盾、检测超时、页面或绑定变化时报告未确认，不记为无广告，也不走无广告快速路径。未识别的标签不直接作为可点击广告，不伪造计数或点击；页面确实无匹配标记和可见标签时仍走快速路径。

入口导航诊断按 executionId 和 PV 关联：每次尝试记录超时预算、主文档响应、主框架提交及 DOMContentLoaded 的相对耗时（-1 表示未观察到），等待期间每约 5 秒记录响应状态、页面匹配、广告候选和可见数量，以及检查超时或页面错误。`navigation_total` 包含有界重试及重试间隔；`post_load_delay`、`ad_detection` 和 `browse_and_read` 分别记录后续阶段，不能将这些时间都归为首次导航。日志反映等待条件和阶段，不自动断言具体网络资源或脚本是根因。

广告检测后，入口只读检查页面及内部滚动容器；确定不存在滚动空间时跳过按次数执行的无效浏览滑动，保留后续随机阅读等待。存在 iframe、检查超时或无法确定时维持原有浏览；页面绑定变化不得继续使用旧绑定。加载后配置等待、点击判断及详情停留预算不受此处理改变。

禁用期间的下载不增加 `TriggerDownloadSign`，不作为广告点击下载或访问成功。启用期间的下载维持原有业务计数和取消行为，包含后续点击打开的页面。

`EntryPageNavigator` 在入口导航期间暂时记录下载 URL、建议文件名，以及能获取到的主框架响应状态、URL、Content-Type、Content-Disposition 和 Location。导航结束时解绑临时诊断监听。

遇到 `Download is starting` 时，在同一个页面和浏览器内等待随机 800–1400ms，再重试一次。第二次仍转为下载，返回明确的入口未打开结果，由主流程跳过当前 PV，不让该异常直接进入 Worker 的通用异常出口；不无限重试，也不把下载当成打开成功。

部分 Chromium 构建会把附件导航报告为 `net::ERR_ABORTED`。仅在短暂等待后确认存在下载事件或附件响应头时，才将其归类为入口下载；没有证据的导航中断继续抛出。

任务取消及其他真实导航故障继续传播。所有 PV 均未成功打开时，任务仍失败并正常回收浏览器；此次改动不承诺在无有效页面时永久保留浏览器。
