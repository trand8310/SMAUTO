# 代理故障与页面错误处理

## 行为

- 代理连接、认证、配置失败独立分类；只有启用代理的任务才使用该分类。
- 主框架导航的隧道/SOCKS路径失败记为 `TargetRoute`，不再比较请求地址与尚未更新的页面地址。这表示当前代理路径不能完成目标访问，不证明该代理对所有网站均失效。
- 普通源站认证、DNS、超时、连接重置和空响应不直接判定代理失效；第三方资源的目标路径失败也不会结束整个任务。
- 浏览器 Context 的 RequestFailed/Response 监听覆盖首页面和新页面，无须等待新页面 CDP 初始化。
- 确认代理故障只记录首次类型和原因，取消本次执行，并以 `BrowserStopKind.ProxyFailed` 回收该执行的浏览器会话。
- `WorkerExecutionResult.ProxyFailure` 上报给 MainClient。当前代理故障后停止该消费任务剩余 UV；不会在当前执行中自动换 IP 或重放可能已执行的点击。
- 主文档 HTTP 407 在代理模式下记为认证失败。403、429、404、5xx 作为页面错误，不认定代理整体失效。
- 入口 HTTP 错误不视为就绪；点击到 HTTP 错误页不计成功、不进入导航阅读延迟；错误页跳过后续可选操作和 PV 停留，不能计为有效访问。
- MainClient 获取远程代理后总是做连通性预检查，获取 IP 元数据仍由原有选项控制。预检查和 Chromium 使用同一代理地址/协议解析，支持 HTTP、HTTPS、SOCKS5，协议冲突和不支持的配置提前拒绝。
- ProxyTester 接收上游取消，采用单次检测总预算，成功或取消后清理其他并发请求，并保留各检测站点错误信息。

## 边界

预检查只能说明当时检测站点的可用性，不能保证之后访问目标站点成功。代理的实际过期时间仍依赖供应商；现有 IpTtl 保持任务时间限制的含义。普通网络错误没有增加周期性探测或自动换 IP。

## 验证

回归覆盖首次导航隧道失败、代理模式隔离、资源故障隔离、并发故障首次记录、结果分类、407/503、访问与点击计数保护、真实 Chromium 代理连接拒绝和真实 HTTP 错误入口。另用本地 TCP 代理夹具验证 HTTP/SOCKS5 握手与检测中取消；无需业务站点或有效外部代理。
