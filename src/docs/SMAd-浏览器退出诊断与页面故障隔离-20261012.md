# 浏览器退出诊断与页面故障隔离

## 本轮结论

现象是 Chromium 窗口退出，MainClient 仍运行。不能仅凭窗口消失判断 Chromium 原生崩溃：业务执行失败后的正常资源回收，也会关闭窗口。

进一步运行真实 `SMAdTask.ExecuteWorkerWithResultAsync` 的完整页面流程，复现了另一个明确的关闭原因：首次点击打开新页面时，Context.Response 先于 popup 的 Frame 建立；`HandleDocumentResponse` 直接读取 Request.Frame 抛出 TargetClosedException，异常进入 Playwright dispatcher，随后连接失效，worker 以 CdpDisconnected 回收浏览器。这个事件监听边界已修复。

修复后又复现新页面设备初始化超时。当前屏幕配置已由定制内核原生完成，但自动附加仍设置 `waitForDebuggerOnStart=true`，使受控新页面导航与初始化互相等待。现在不暂停新页面启动，输入前仍等待触屏初始化完成。最终两轮完整流程均通过：

| 站点策略 | 首次跳转 | 二跳 | 详情停留 | 结算与回收 |
| --- | --- | --- | --- | --- |
| 爱采购 | 新页面，成功 | 同页面，成功 | 完成 | PV=1、点击 PV=1、Completed、退出确认 |
| 1688 | 同页面，成功 | 新页面，成功 | 完成 | PV=1、点击 PV=1、Completed、退出确认 |

这两轮使用 145.0.7632.110、有界面、隐身、TTL 180 秒、不使用代理，并沿用保存的加载和阅读设置。全部浏览器请求由路由返回受控 HTML；触屏输入、页面绑定、站点策略、导航观察、统计结算和资源回收均使用生产实现。没有点击线上广告或提交任务/统计。设备来自本地目录样本，测试固定单 PV、100% 点击分支及 8–12 秒详情停留，不等同于某次线上任务参数的逐项重放。两轮耗时分别约 73 和 84 秒。结束后的强制回收由测试任务完成触发，不是运行中原生崩溃。

使用修改前发布目录中的 SMAd.dll，与受控 CDP 端点做对照，复现了单个页面初始化返回 `Session with given id not found` 时触发整个浏览器故障回调的问题。生产回调会 RequestStop 并取消执行，最终回收浏览器。这是已确认的误关闭路径；尚不能证明用户每一次偶发退出都由它导致。

本轮按保存配置进行了 10 轮页面操作：145.0.7632.110、有界面、隐身、TTL 180 秒、关闭代理。包含本地真实触屏点击、点击后 DOM 读取、滚动定位、触屏打开弹窗和观察，以及实际神马搜索页面的加载和滑动；后 8 轮还包含实际搜索输入框触屏点击、每轮 12 次快速创建/关闭页面。全部完成，回收前进程仍存活且 CDP 连接正常。本轮没有复现 Chromium 原生进程崩溃。

设备采用当前 `UsingDevIndex=1` 对应的本地设备目录样本，按生产方式规范化 UA/版本；目录中的 storage 变体选择一个值。没有请求设备/任务接口、上报业务统计或点击广告。样本与当前保存的配置一致，不等同于某次线上任务完整参数的重放。

## 修改

- `DeviceTargetController` 将每个目标的就绪状态绑定到 session。旧会话迟到的分离事件只移除自己的状态，不移除同页面的新会话状态。
- 单目标初始化失败只记录该目标错误，尝试解除等待并分离故障 session，不直接按 targetId 关闭页面，也不触发浏览器级故障回调。选择使用故障页面的调用方仍会收到初始化失败；真正的设备 CDP 连接断开仍是执行级故障。
- 入口导航超时、连接重置、空响应和连接超时最多在同一浏览器重试一次，间隔 800–1400 毫秒。明确代理故障、无下载证据的 ERR_ABORTED 不进入这条恢复路径。连续失败返回失败结果，不伪造访问成功；所有 PV 均失败时仍正常回收。
- 业务失败不再默认标记为 Completed。新增 ExecutionFailed 和 DeviceConfigurationFailed；输出执行阶段、耗时与关闭原因。
- 原生屏幕验证继续严格执行，错误同时记录期望屏幕/可用屏幕/DPR 与实际读取结果，不增加 JS 或 device metrics 回退。
- Chromium 管理器异步排空 stderr，保留最后 32 行，每行最多 1000 字符。回收结果和日志保留真实退出码、是否被强制结束及原生诊断。启动前主动退出不再标记 Completed。
- 移除 SMAd 启动参数中重复的 user-data-dir，独立用户目录由 ChromiumSessionManager 统一设置。
- Context 响应监听安全处理尚无 Frame 的导航请求；明确代理故障仍独立识别。页面就绪后通过只读 navigation performance 状态补查主文档 HTTP 错误，避免跳过响应归属时把错误页计为成功。
- 新目标自动附加改为 `waitForDebuggerOnStart=false`，不重新引入 CDP 屏幕覆盖。设备命令超时明确记录 method 和 session，便于区分初始化阻塞与连接断开。

## 调试命令

先构建 CdpInput.RegressionTests，然后从 src 执行：

```powershell
& './tests/CdpInput.RegressionTests/bin/Debug/net8.0/CdpInput.RegressionTests.exe' --full-page-flow --rounds=2
& './tests/CdpInput.RegressionTests/bin/Debug/net8.0/CdpInput.RegressionTests.exe' --startup-diagnostic --rounds=6 '--url=https://wm.m.sm.cn/s?from=wm100000&q=%E5%A4%A9%E6%B0%94'
```

`--full-page-flow` 会调用真实 worker，依次检查入口、首次跳转、二跳、详情停留、结算和回收，任何环节缺失均返回非零退出码。保存配置的 HompageTrigger 必须为 0。它在导航前拦截所有请求，与仅做输入操作的 startup diagnostic 是两个不同的验证入口。

`--base=<目录>` 指定包含 appsettings.user.json、File/chrome-win 和 Data 的客户端输出目录，默认 Build/publish。`--url` 会真实访问指定页面；省略时只操作本地夹具。测试不提交任务、不上报统计，报告写入 artifacts/browser-operation-*。

报告中的 ExitedBeforeCleanup/ConnectedBeforeCleanup 表示调试程序主动清理之前的状态，不能把最后的主动回收当成自然崩溃。调试失败返回非零退出码，并记录失败阶段和异常。

原发布程序集已保存为六轮报告目录中的 baseline-SMAd.dll，可用于受控协议对照：

```powershell
& './tests/CdpInput.RegressionTests/bin/Debug/net8.0/CdpInput.RegressionTests.exe' --target-controller-baseline './artifacts/browser-operation-20261012-220542-2832a49e4f21445289f31fb16e4441fa/baseline-SMAd.dll'
```
